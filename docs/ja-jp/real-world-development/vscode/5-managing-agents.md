GitHub Copilot を agent mode で使うと、コードベースの調査、変更の提案、ファイル編集、コマンド実行を自律的に行います。作業は開発者のマシン上でリアルタイムに進むため、VS Code の Copilot Chat には、ツール呼び出しとファイル編集が逐一表示されます。差分をインラインで確認し、変更ごとに受け入れるか拒否するかを選び、エディターを離れずに追加のプロンプトで作業を誘導できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムに監視します。
- 提案されたファイル編集をレビューして受け入れます。
- セッションの途中でエージェントを誘導し、ハイコントラストに加えてライトモードの切り替えを追加します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、ハイコントラストモードを実装しています。作業中にデザインチームから追加の依頼がありました。既定のテーマを暗すぎると感じるユーザー向けに、ライトモードへの切り替えも追加してほしいとのことです。会話を最初からやり直すのではなく、既存のセッションを誘導して作業を拡張します。

## Copilot の進捗を監視する

Copilot Chat ビューには、エージェントが行った操作が順番に表示されます。調査したファイル、実行したコマンド、提案した編集を確認できます。各ファイルの編集は、差分と **Keep** / **Undo** 操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. ファイルの編集が提案されると、差分がインラインに表示されます。
    - **Keep** を選択すると変更が適用されます。
    - **Undo** を選択すると変更が元に戻り、エージェントは再度作業します。
4. チャット上部の **Files changed** を開き、セッションでエージェントが変更したファイル全体を確認することもできます。

> [!NOTE]
> ツール呼び出しで (たとえばターミナルコマンドの実行時に) 許可を求められると、エージェントは一時停止して **Allow** を表示します。内容を確認し、許可できるコマンドだけを承認してください。

5. エージェントがハイコントラストモードの実装を終えるまで待ちます。変更内容をまとめた最終メッセージが表示されます。

## エージェントを誘導してライトモードを追加する

ハイコントラストモードができたら、同じ会話を続けてライトモードの切り替えを追加します。既存のチャットセッションを続けるため、エージェントはこれまでの作業で変更したコンポーネント、スタイルの方法、ローカルストレージのパターンを把握しています。

1. Copilot Chat の入力欄に次のフォローアッププロンプトを送信します。

    ```plaintext
    Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
    ```

2. エージェントは既存の変更を調べ、ライトモードの追加を提案します。
3. ハイコントラストの場合と同じように、各編集を確認して **Keep** または **Undo** を選択します。
4. エージェントの方向性が希望と異なる場合 (たとえば切り替え UI のリファクタリング方法が適切でない場合) は、チャット入力欄の横にある **Stop** ボタンで停止し、明確化するフォローアップメッセージを送信します。

> [!TIP]
> 進行中のセッションを誘導すると、最初からやり直すよりすばやく作業できます。フォローアッププロンプトで調整 ("CSS を簡潔にし、セレクターの重複ではなく CSS 変数を使う")、軌道修正 ("3つ目の切り替えを追加せず、既存の設定パネルにライトモードを統合する")、範囲の拡張 ("両方の切り替えにキーボードショートカットを追加する") を依頼できます。

## 作業内容をレビューする

コミットする前に、エージェントが変更したファイルを確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連テストなどが更新されています。
3. 変更ファイルをいくつか開き、差分を確認します。カスタムエージェントのアクセシビリティパターン (Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティック HTML、ローカルストレージによる保持) が反映されていることを確認します。
4. 問題がなければ、Source Control パネルから変更をステージしてコミットします。次のレッスンで公開します。

## まとめと次のステップ

Copilot Chat agent mode を使い、進行中のセッションを監視して誘導しました。ファイル編集を確認しながら受け入れまたは拒否し、コンテキストを保ったままフォローアッププロンプトで作業を拡張しました。

このレッスンでは、次のことを確認しました。

- エージェントの作業をリアルタイムに監視する。
- ファイル編集を個別に受け入れる、または拒否する。
- セッションの途中でフォローアッププロンプトを使って方向付ける。

次は、アクセシビリティ機能の作業をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが作成した変更をレビューします。
